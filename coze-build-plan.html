一、搭建阶段计划（7 阶段）

整个搭建过程分为 7 个阶段，严格按依赖顺序推进。每个阶段有明确的前置依赖、核心任务和预期产出。

P0

账号注册 & Bot 创建

注册扣子（Coze）账号，创建空白 Bot，选定底层大模型。

  • 注册 coze.cn 账号（推荐国内版，支持微信小程序发布）
  • 创建 Bot → 选择"自定义创建"
  • 模型选型：对话生成选 GLM-4 或豆包 Douban-Pro；向量化用默认 embedding

预期产出：一个可运行的空壳 Bot，能进行基础文字对话。

P1

Bot 人设 & Prompt 设计

为 Bot 注入"工友一站式管家"的灵魂——这是所有后续组件的协作基础。

  • 角色设定："你是建筑工友的贴心管家，擅长用大白话解释法律问题"
  • 通俗化翻译指令：所有法律条文回复必须用"工友能听懂的话"重新表述
  • 安全边界规则：涉及自杀/自残倾向 → 立即转接心理热线；涉及暴力 → 转接法务
  • 开场白 & 引导语设计

预期产出：一个有"人味"的基础 Bot，能对工友的咨询给出语气亲切的回复。

P2

知识库构建（RAG 核心）

这是方案文档中明确要求的 P0 优先项——确保 AI 只引用真实法条，不编造。

  • 收集资料：《劳动法》《劳动合同法》《工伤保险条例》《保障农民工工资支付条例》等
  • 上传至 Coze 知识库（支持 PDF/Word/TXT）
  • 配置分段策略：按"条"分段，保留条文编号
  • 向量化配置：使用 Coze 默认 embedding 模型
  • 检索策略：混合检索（向量+关键词），召回 top-5

预期产出：Bot 能基于真实法规条文回答问题，并在回复中标注引用来源。

P3

Workflow 工作流编排

这是 Coze 的核心能力——用可视化工作流实现"意图路由→分支处理→安全判断→转接/回复"的完整链路。

  • 意图路由节点：用 LLM 分类用户意图为「权益咨询/心理陪伴/便民工具」三类
  • 权益咨询工作流：知识库检索 → LLM 组织回答 → 标注引用
  • 心理陪伴工作流：情绪识别 → 轻度疏导话术 → 高危识别 → 转接阈值判断
  • 便民工具工作流：宿舍报修/食堂反馈/班车查询的占位逻辑

预期产出：三条主流程能跑通，用户输入能被正确分流到对应处理路径。

P4

语音 & 插件交互模块接入

实现方案中强调的"语音交互优先"——这是工友群体的核心使用门槛降低手段。

  • ASR 语音识别插件：配置语音输入能力（Coze 内置或接入第三方）
  • TTS 语音合成插件：回复自动语音播报
  • OCR 图片识别插件：工友可拍照上传工资条/合同（Coze 多模态插件）
  • 转接通知插件：模拟"转接 HR/法务/心理热线"的动作（可先用卡片消息占位）

预期产出：用户可通过语音输入对话，Bot 可语音回复，支持图片上传识别。

P5

Memory 记忆 & Database 数据模块

实现多轮对话记忆和工友档案持久化——让 AI"记住"工友之前说过的问题。

  • 对话记忆变量：配置 Coze Memory，保留最近 N 轮对话上下文
  • 工友档案表（Database）：建表字段：user_id / 工种 / 入职日期 / 历史咨询摘要
  • 工单记录表：记录每次咨询的问题类型、AI回复、是否转接
  • 长期记忆写入：每次对话结束后，摘要写入工友档案

预期产出：Bot 能记住上下文，支持多轮追问（如先说"老板不发工资"，再补充"已经三个月了"）。

P6

发布 & 测试 & 调优

将 Agent 发布到评委可体验的渠道，进行端到端测试与 Prompt 调优。

  • 发布渠道：优先发布为 Coze Web 链接（评委直接体验）；有条件同步发微信小程序
  • UI 布局确认：确保界面包含输入框 + 语音输入按钮 + 图片上传按钮
  • 端到端测试：模拟工友张三的全流程——语音咨询欠薪 → AI 回答 → 转接
  • Prompt 调优：反复测试法律幻觉问题，确保 AI 不编造法条
  • 方言测试：用四川话/河南话测试语音识别容错能力

预期产出：一个可体验的 MVP 成品 + 可提交给评委的体验链接。

依赖关系总结 P0 → P1 → P2 → P3 → P4 → P5 → P6，严格串行。其中 P2（知识库）和 P3（工作流）是技术核心，建议投入最多时间。P4 和 P5 可部分并行（语音插件和数据库配置互不依赖），但需在 P3 工作流跑通后才有意义。

三、组件间数据流转与调用关系

以下是用户一次输入的完整数据流转路径，标注了每一步涉及的组件和数据格式。

主流转路径（6 步）

  1. 用户输入 → 语音/文字/图片，经 ASR/OCR 统一转为文本
  2. 意图路由器 → LLM 分类为「权益/心理/便民」三类，分发到对应 Workflow
  3. 分支工作流执行 → 权益咨询查 RAG 知识库；心理陪伴查 疏导库；便民工具执行占位逻辑
  4. 安全阈值判断 → 权益问题超复杂 → 转人工；心理高危 → 转热线；便民 → 直接回复
  5. 回复合成 → LLM 组织通俗化回复 + 写入 Memory + 写入 Database
  6. 输出 → 文字展示 + TTS 语音播报 + 转接卡片（如触发）

四、搭建顺序与依赖关系

关键依赖链 P0（账号+Bot） → P1（人设+Prompt） → P2（知识库） → P3（工作流） → P4（语音插件） → P5（记忆+DB） → P6（发布测试）

依赖关系详解

阶段前置依赖阻塞下游可并行项
P0 账号注册无P1-P6 全部—
P1 人设 PromptP0P2-P6—
P2 知识库P0（知识库功能需 Bot 存在）P3（工作流需调用知识库）可与 P1 后期并行
P3 工作流P1（需 Prompt 基础）+ P2（需知识库可调用）P4-P6—
P4 语音插件P3（工作流需先跑通）P6可与 P5 并行
P5 记忆 DBP3（工作流需先跑通）P6可与 P4 并行
P6 发布测试P0-P5 全部——

并行优化建议

  • P1 后期 + P2 全程可并行：Prompt 初稿写完后，知识库收集和上传可同步进行
  • P4 + P5可并行：语音插件配置和数据库建表互不依赖
  • P6 的"发布"和"调优"可迭代循环：先发布再持续调优 Prompt

风险与对策

风险1：AI 法律幻觉 对策：P2 知识库分段保留条文编号，P3 工作流强制标注引用来源，P6 测试中反复验证法条准确性。
风险2：方言识别失败率 对策：P4 选 Coze 内置 ASR 的方言模型，P6 用四川话/河南话做容错测试；如效果差，Prompt 中加"请用标准普通话重述"引导。
风险3：心理陪伴越界 对策：P1 Prompt 中明确"只做轻度疏导，不做诊断"；P3 工作流加高危关键词检测（自杀/不想活），命中即转接。
