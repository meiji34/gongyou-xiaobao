# 工友管家 — 工作流逻辑定义

本文档定义 Agent 的意图路由和各分支工作流的执行逻辑。

---

## 1. 意图路由器

### 输入
用户文本（经 ASR 转换或直接输入）

### 分类逻辑

```
输入用户文本
    │
    ├─ 关键词匹配（第一层快速匹配）
    │   ├─ 工资/欠薪/拖欠/工伤/合同/社保/加班/辞退/赔偿/试用期 → 权益咨询
    │   ├─ 想家/累/烦/压力/睡不着/难过/想哭/不想活/没意思/吵架 → 心理陪伴
    │   ├─ 报修/食堂/班车/宿舍/水电/空调/饭/车 → 便民工具
    │   ├─ 安全/危险/防护/操作/规程 → 安全教育
    │   └─ 其他 → 闲聊/默认
    │
    └─ 语义理解（第二层兜底）
        └─ 如果关键词未命中，用 LLM 语义判断属于哪个类别
```

### 输出
```json
{
  "intent": "rights_consultation | mental_support | convenience_tools | safety_education | chitchat",
  "confidence": 0.0-1.0,
  "raw_input": "用户原文"
}
```

## 2. 权益咨询工作流

```
用户问题
    │
    ├─ 1. 信息提取
    │   提取：问题类型/持续时间/金额/是否协商过
    │
    ├─ 2. 法律检索
    │   ├─ 有 Skill：调用 fadada/fazhi-law 检索相关法条
    │   └─ 无 Skill：基于自身知识，标注"需法务确认"
    │
    ├─ 3. 通俗化翻译
    │   将法条翻译成工友能听懂的话
    │
    ├─ 4. 分步建议生成
    │   生成"第一步…第二步…第三步…"
    │
    ├─ 5. 安全阈值判断
    │   ├─ 拖欠>3月 + 协商无果 → 附转接卡片（法务）
    │   ├─ 工伤 + 未认定 → 附转接卡片（HR）
    │   ├─ 金额>5万 → 附转接卡片（法务）
    │   └─ 用户要求转人工 → 附转接卡片
    │
    └─ 6. 输出回复
        格式：共情开头 + 核心回答 + 分步指引 + 法条卡片 + 转接卡片（如有）
```

### 信息提取字段

| 字段 | 类型 | 说明 |
|------|------|------|
| problem_type | string | 工资拖欠/工伤/合同纠纷/社保/加班/辞退/其他 |
| duration | string | 持续时间（如"三个月"） |
| amount | number | 涉及金额（如有） |
| negotiated | boolean | 是否已协商过 |
| has_contract | boolean | 是否有劳动合同 |
| detail | string | 其他细节 |

## 3. 心理陪伴工作流

```
用户输入
    │
    ├─ 1. 情绪识别
    │   ├─ 检测高危关键词（不想活/想死/了结/跳楼）
    │   ├─ 检测中危关键词（没意思/太累了/不想撑了）
    │   └─ 常规情绪（想家/烦/累/压力）
    │
    ├─ 2. 分流
    │   ├─ 极危 → 立即输出高危回复 + 转接心理热线
    │   ├─ 高危 → 深度疏导 + 建议拨打热线
    │   └─ 常规 → 常规陪伴流程
    │
    ├─ 3. 常规陪伴流程
    │   ├─ 共情回应（"这种感觉一定很难受"）
    │   ├─ 正常化（"很多人都会有这种感觉"）
    │   ├─ 轻度建议（运动/找人聊/给家人打电话）
    │   └─ 继续倾听（"愿意跟我说说更多吗"）
    │
    └─ 4. 记忆写入
        更新工友情绪状态（正常/需关注/高危）
```

### 高危关键词清单

| 级别 | 关键词 | 响应 |
|------|-------|------|
| 🔴极危 | 不想活了、活不下去、想死、自杀、了结、跳楼、割腕 | 立即转接12320-5 |
| 🟡高危 | 活着没意思、没意义、太累了不想撑了、撑不下去了 | 深度疏导+建议热线 |
| 🟢常规 | 想家、累、烦、压力大、睡不着、难过、想哭、吵架 | 常规陪伴 |

## 4. 便民工具工作流

```
用户输入
    │
    ├─ 宿舍报修分支
    │   ├─ 询问故障类型（水电/门窗/家具）
    │   ├─ 询问宿舍号
    │   ├─ 生成报修单 {dorm: "X号楼X号", type: "水管漏水", time: "2026-08-05"}
    │   └─ 回复"已登记，维修师傅会尽快"
    │
    ├─ 食堂反馈分支
    │   ├─ 询问好评/差评
    │   ├─ 差评→追问具体问题（口味/分量/卫生/价格）
    │   ├─ 生成反馈单 {rating: "差", issue: "分量少", time: "2026-08-05"}
    │   └─ 回复"已记录，会转告食堂"
    │
    ├─ 班车查询分支
    │   ├─ 提供当日时刻表
    │   ├─ 询问目的地
    │   └─ 匹配最近一班
    │
    └─ 安全微课分支
        ├─ 获取当前星期
        ├─ 匹配对应话题
        └─ 输出安全知识卡片
```

## 5. 工作流选择伪代码

```python
def route_intent(user_input):
    # 第一层：关键词匹配
    rights_keywords = ["工资", "欠薪", "拖欠", "工伤", "合同", "社保", "加班", "辞退", "赔偿"]
    mental_keywords = ["想家", "累", "烦", "压力", "睡不着", "难过", "想哭", "不想活"]
    tool_keywords = ["报修", "食堂", "班车", "宿舍", "水电"]
    safety_keywords = ["安全", "危险", "防护", "操作"]

    if any(kw in user_input for kw in rights_keywords):
        return "rights_consultation"
    elif any(kw in user_input for kw in mental_keywords):
        return "mental_support"
    elif any(kw in user_input for kw in tool_keywords):
        return "convenience_tools"
    elif any(kw in user_input for kw in safety_keywords):
        return "safety_education"
    else:
        # 第二层：LLM 语义判断
        return llm_classify(user_input)

def mental_safety_check(user_input):
    critical = ["不想活", "活不下去", "想死", "自杀", "了结", "跳楼"]
    warning = ["没意思", "没意义", "撑不下去"]

    if any(kw in user_input for kw in critical):
        return "critical"
    elif any(kw in user_input for kw in warning):
        return "warning"
    return "normal"
```

## 6. 数据流转总览

```
用户语音/文字输入
    │
    ├─ [语音] ASR转文字
    ├─ [图片] OCR转文字
    │
    └─ 统一文本
        │
        ├─ 意图路由器 → 分类
        │
        ├─┬─ 权益咨询 → 法律检索 → 通俗化 → 安全阈值 → 回复
        │ └─ Memory注入工友档案
        │
        ├─┬─ 心理陪伴 → 情绪识别 → 高危检测 → 疏导/转接
        │ └─ 更新情绪状态到Memory
        │
        ├─ 便民工具 → 生成工单 → 回复
        │
        └─ 安全教育 → 匹配话题 → 输出卡片
            │
            └─ 回复合成
                ├─ 文字展示
                ├─ TTS语音播报
                └─ Memory摘要写入
```
